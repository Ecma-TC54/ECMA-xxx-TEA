Terms and definitions

Terms

For the purposes of this Standard, the following terms and definitions apply:

Authentication (authn)

process of verifying the identity of a principal

Authorization (authz)

process of determining what a verified principal is permitted to do

Collection

versioned list of the TEA Artifacts of one Component Release or one Product Release

Note 1 to entry: A Collection has the same UUID as the release it belongs to. A change to its content produces a new version, which records the reason for the change.

Compliance document

document describing the compliance, certification or regulatory status of a Component, for example a SOC 2 report

Note 1 to entry: A compliance document is published as a TEA Artifact of a Component Release. The Component or Component Release is marked with the COMPLIANCE_DOCUMENT identifier type so that it can be discovered.

Component

software or hardware item whose successive versions are Component Releases

Note 1 to entry: A Product Release can reference Components and specific Component Releases.

Component Release

specific version of a Component

Note 1 to entry: Each Component Release has its own Collection.

Discovery document

JSON document served at /.well-known/tea on the host named by the domain name of a TEI, listing the TEA server endpoints for that domain and the API versions they support

Product

item sold, distributed or otherwise delivered under one name

Product Release

specific version of a Product that can be acquired or downloaded

Note 1 to entry: A TEI resolves to one or more Product Releases.

Software bill of materials

SBOM

structured inventory of the software components of a product, with their versions, identifiers and dependencies

Note 1 to entry: CycloneDX, specified in ECMA-424, is one format for SBOMs.

TEA Artifact

security-related document, such as an SBOM, a VEX document or an attestation, published in one or more formats and identified by a UUID and a version

Note 1 to entry: A TEA Artifact can be referenced by several Collections.

TEA client

software that retrieves information from a TEA server using the API defined in this Standard

TEA server

server that implements the API defined in this Standard

Transparency Exchange Identifier

TEI

URI of the form tei://<domain-name>/<type>/<unique-identifier> that identifies one or more Product Releases

Note 1 to entry: The domain name of a TEI is used to locate the TEA server; see the Discovery chapter.

Vulnerability Exploitability eXchange document

VEX document

document stating, for a product, the exploitability status of known vulnerabilities

Note 1 to entry: A VEX document states, for example, whether a vulnerability affects the product, does not affect it, or is mitigated.
