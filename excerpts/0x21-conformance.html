Conformance

This Specification defines two conformance classes: TEA server and TEA client. An implementation may conform to either or both.

A conformant TEA server shall:

  • Implement the operations defined in , except those that this Specification makes optional for it.
  • Support the discovery of its API as defined in the Discovery chapter.
  • Honour the authentication and authorization model defined in the Authentication chapter.
  • Assign TEA UUIDs with the uniqueness and stability defined in the UUID Scope and Stability chapter.
  • Return payloads that conform to .

A conformant TEA client shall:

  • Resolve Transparency Exchange Identifiers as defined in the Discovery chapter.
  • Authenticate, where a TEA server requires it, as defined in the Authentication chapter.
  • Send requests that conform to .

The verbal forms in this Specification follow ISO/IEC Directives, Part 2: shall and shall not indicate requirements; should and should not indicate recommendations; may and need not indicate permission; and can and cannot indicate possibility or capability. The verbal form must is used only for external constraints and does not express a requirement of this Specification.
